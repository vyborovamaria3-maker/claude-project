# tgparser-cli archive integration

The native backend can import **existing** JSON/CSV exports generated by
[VibeBrainsProjects/TgParser](https://github.com/VibeBrainsProjects/TgParser)
(MIT-licensed project). This adapter is independently implemented against
its documented message schema; no external package needs to be installed.

It does **not** log in to Telegram, scrape groups, enumerate members, send
invitations or bypass any channel restrictions.

## Usage

Run from `solana-launcher/backend` with the normal configured database:

```bash
python -m app.cli.telegram_import_tgparser data/my-channel.json --channel-id 42
python -m app.cli.telegram_import_tgparser data/my-channel.csv --channel-id 42
```

`--channel-id` refers to an **existing** `telegram_channels.id`.
The archive's `channel` field must match that record's username or title.
The importer does not automatically create or discover channels.

### Behavior and privacy

- Processes at most 500 messages per transaction; 20 MiB input file limit.
- Existing `(channel_id, telegram_message_id)` records are not overwritten.
  Re-running the same archive is idempotent.
- Validates message ID, ISO timestamp, source identity, text length and reaction counts.
- Stores message text, timestamp, total reactions and source marker.
- Does **not** import message authors, Telegram user IDs, phone numbers, media links,
  access hashes or other arbitrary raw-source fields.
- Naive source timestamps are interpreted as UTC and marked `assumed_utc=true`.
- Imported archive entries do not create token mentions/calls. Archive content
  should not silently acquire the same provenance as directly collected MTProto data.
- Retention and data access policies are those of the existing Telegram message database.

This imports **existing user-provided archives** only. For live collection use
the authorized MTProto collector and its separate historical backfill flow.
