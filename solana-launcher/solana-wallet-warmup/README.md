# Solana Wallet Warmup - Anti-Detect Module

Anti-detect warmup script for Solana wallets. Simulates natural retail user activity to bypass Sybil filters (Nansen, Chainalysis, LayerZero, etc.).

## Features

### Anti-Detect Strategies
- **Time-based randomization**: Actions spread over days/weeks with realistic sleep patterns
- **Amount randomization**: Human-like decimals (1.0234 SOL vs 1.0 SOL)
- **Personality profiles**: Each wallet gets unique behavior (trader, holder, degen, casual)
- **Error simulation**: Human-like mistakes (failed transactions, cancellations)
- **Multi-source funding**: Breaks transaction graph analysis
- **Protocol diversity**: 4-5 different protocols per wallet

### Supported Actions
- **Swaps**: SOL → USDC/RAY/ORCA/BONK via Jupiter (random slippage 0.5-3%)
- **Staking**: Native, Marinade (mSOL), Jito (jitoSOL)
- **Lending**: Solend, Marginfi (with leverage scenarios)
- **NFTs**: Cheap NFT purchases on Magic Eden/Tensor
- **Bridging**: Wormhole, Mayan Finance

## Installation

```bash

```

## Configuration

1. Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```

2. Edit `.env`:
```env
# Your private RPC (Helius/QuickNode recommended)
RPC_URL=https://mainnet.helius-rpc.com/?api-key=YOUR_KEY

# Master wallets (comma-separated base58 private keys)
# These should be from different sources (exchange, personal, etc.)
PRIVATE_KEYS=your_key1_here,your_key2_here,your_key3_here

# Number of child wallets per master
WALLETS_PER_MASTER=3

# Delay between actions (seconds)
MIN_DELAY_SECONDS=3600      # 1 hour
MAX_DELAY_SECONDS=172800    # 48 hours

# Simulation mode (true = no real transactions)
SIMULATE=false
```

## How It Works

1. **Master Wallets**: Your funded wallets (from exchanges, etc.)
2. **Child Wallets**: New wallets generated by the script
3. **Funding**: Each child gets random amount (0.05-0.5 SOL) from master
4. **Initial Sleep**: Child wallets "sit idle" for 3-14 days (simulated)
5. **Action Sequence**: Each wallet gets unique sequence of 5-12 actions
6. **Execution**: Actions executed with random delays (1-48 hours between)

## Output Files

- `wallets/`: Child wallet keypairs (keep secure!)
- `plans.json`: Execution schedules for each wallet
- `summary.json`: Final results
- `logs/warmup-YYYY-MM-DD.log`: Detailed execution logs

## Troubleshooting

### "Insufficient balance"
- Master wallets need SOL for funding + transaction fees
- Each child needs 0.05-0.5 SOL + ~0.01 for fees

### "RPC rate limit"
- Use private RPC (Helius, QuickNode)
- Add multiple RPCs to `src/config.ts`

### "Transaction failed"
- Check priority fees (automatically randomized)
- Some protocols may be congested
- Check logs for details
