# Локальная проверка PR #68 — 15.10.2026

Проверена ветка `feat/solana-onchain-evidence-20261015`, исходный commit `41b21319`. PR основан на ветке PR #65, а не на main; настройки из PR #67 автоматически в него не входят. Слияние не выполнялось.

## Исправления

- Воспроизведена ложная подтверждённая прибыль: продажа `1e-12` токена без покупки давала verified PnL. В обоих FIFO убран абсолютный порог, пропускавший расход маленьких количеств. Проверены также частично известная себестоимость и корректный маленький лот.
- Сверка токенов больше не скрывает малые расхождения абсолютным допуском; изменение SOL сверяется до лампорта. Несогласованная операция остаётся unpriced.
- Операции кошелька в API содержат wallet, который необходим интерфейсу. Экран токена показывает и дедуплицирует сделки из DEX и seed-кошельков. Незавершённые запросы отменяются, отсутствующий адрес не вызывает падение рендера.
- API доказательств использует существующую production-авторизацию до чтения SQLite.
- Версии проекций повышены: forensic v5, DEX v3. API не показывает устаревшие декодированные сделки и PnL как актуальные доказательства до пересчёта.

## Проверки

Успешны `blockchain:test`, `blockchain:integration-test`, полный `build` с analysis-регрессиями и TypeScript, `security:test`, новый тест API с настоящим SQLite. Полный ESLint: 0 ошибок, 346 предупреждений. Новые проверки API и финансовых граничных случаев включены в analysis-тесты CI.

Браузерная проверка production-сборки: реальный API возвращает 401 без авторизации; wallet и mint представления отображают тестовые операции на экране 390 px без исключений JavaScript и горизонтального переполнения. Интерфейс проверялся на изолированных тестовых ответах; это не заявление о полноте реальной истории. Платный RPC для этих проверок не использовался.

## Пересчёт сохранённого кэша

Существующие CLI пересчитывают проекции без сетевых запросов, из каталога solana-launcher:

```sh
npm run blockchain:forensics -- --limit 100
npm run blockchain:dex-replay -- --limit 1000
```

DEX replay обрабатывает программы из уже настроенной `CHAIN_DEX_PROGRAM_IDS`. Для больших баз повторять ограниченными пакетами. Исходные транзакции сохраняются; новый декодер не превращает неполную историю или Excel-категорию в доказательство прибыли, миграции или общего владельца адресов.
