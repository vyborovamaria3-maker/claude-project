# Twitter exact-address author outcomes

Python 3.11+, psycopg 3 and python-dotenv (local runtime already has them).
Environment: AUTHOR_OUTCOMES_DSN (collector writer), AUTHOR_OUTCOMES_DIRECTORY (private report/evidence directory). Do not use the admin read-only role for the worker. Admin only needs AUTHOR_OUTCOMES_DIRECTORY.

Initial deployment: python worker.py --migrate --backfill; then run worker.py under the existing Windows supervisor. --once performs one bounded scan/pricing pass. Schema is additive and idempotent; its source-update index supports resumable scanning. One advisory lock fences writers; each batch and its cursor commit together. Default scan is at most 100,000 updated rows/tick, then four priced token/date windows. Provider requests are paced at least seven seconds apart; 429 triggers a persistent global 15-minute pause. Missing histories retry after 12 hours. No LLM calls.

The initial 1,465,650-row scan found 33,072 post/address candidates, 8,638 distinct addresses, 5,420 authors. Candidates include wallets; only validated Solana pool-token membership is bridged into tweet_token_links. The worker owns only links it inserted and preserves pre-existing links. Later source edits retract owned links when the address disappears; changed text hashes invalidate earlier outcomes in reports. Source deletion cascades to prevent blocking collector retention. Registry candidates can be rescanned incrementally after collection resumes.

Selection is the earliest active stored mention per (lowercase author, mint), not every repost. An incomplete archive can move this first mention. Five-minute USD OHLCV is anchored to the publication and +73h, not substituted from current spot quotes. Entry: first traded candle open at/after publication within five minutes. Exits: opens at/after entry+1/24/72h within five minutes. Only finished candles with positive trade volume qualify. Gross=exit/entry-1; net=exit*0.99/(entry*1.01)-1. Evidence preserves pool identity, side, lookup/price URLs, retrieval time, candles and SHA-256; source text and its hash accompany each example. Registry and link writes are not presented as verified executed trades.

This is a hypothetical mention markout, not author PNL or an inferred buy recommendation. Historical pool liquidity/execution, intent and out-of-sample predictive performance are not established. Current-pool selection and unavailable historical prices produce survivorship/coverage bias. Missing outcomes remain unknown. Retrospective and prospective observations are labelled separately; prospective requires collection and linking within five minutes of publication. UI marks fewer than 20 tokens or 10 publication days as small samples; exceeding the threshold does not prove skill. Repeated messages do not inflate token count. No validated profitable author has yet been established.

Admin: authenticated /api/author-outcomes and /api/author-outcomes/evidence/{sha}; UI #author-outcomes. Reports show up to 100 author/horizon rows, 60 outcome proofs and 30 candidate examples; underlying database retains the full dataset. Both HTTP routes are read-only, use no-store, bound file size and restrict evidence by hash. UI uses textContent and fixed external-link hosts. Run test_core.py and admin tests/test_author_outcomes.py; transactional fixture test work/test-author-outcomes-db.py validates scan idempotency, validation bridge, removals, first-mention dedup and pre-existing link preservation without persisting fixtures.
