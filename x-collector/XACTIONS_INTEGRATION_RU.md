# XActions: безопасная интеграция (черновик, только рабочая ветка)

Статус: реализованы изолированные примитивы. **Рабочий парсер не переключён.**
Рабочий репозиторий: `feature/xactions-http-engine`.
Исходная версия XActions: `nirholas/XActions` 3.5.0, commit
`b9c4bf7bd680f82d4ede0a1b48bb1c5dbfd7bb78`.

## Что добавлено

- `src/xactions/normalize.ts`: преобразование формата публикаций и профилей XActions
  к текущим типам X Collector; неизвестные счётчики не записываются как реальные нули.
  Важно: XActions 3.5.0 сам преобразует ряд отсутствующих счётчиков в `0`, поэтому
  нормализатор консервативно преобразует неположительные значения в `null`.
- `src/xactions/pagination.ts`: источник страниц + асинхронный `commitPage`.
  Следующий HTTP-курсор допускается лишь после успешного завершения `commitPage`.
- `src/xactions/errors.ts`: адаптация ошибок 429/401/403/404 к классификатору X Collector.
- `src/xactions/engine.ts`: read-only GraphQL адаптер профиля/ленты/списка, пока с внедряемыми клиентом и парсерами (не подключён к worker).
- `migrations/041_xactions_checkpoints.sql` и `src/xactions/checkpoint-store.ts`: отдельное состояние HTTP-курсоров; запись страницы и курсора в общей транзакции PostgreSQL.
- `src/xactions/persist.ts`: транзакционная обёртка вокруг существующего `persistTweets`; существующий вызов по умолчанию не меняется.
- `src/xactions/transport.ts`: ограниченный `fetch` через SOCKS5;
  **без прямого сетевого fallback**, с отменой запросов и тайм-аутом.
- `tests/xactions-http.test.ts`: автономные тесты без X и реальных аккаунтов.

## Не сделано и пока НЕ включать

- Подключение и установка конкретной версии XActions как зависимости.
  Пакет XActions 3.5.0 требует Node.js >=22.12, а X Collector сейчас заявляет >=20.
  До принятия решения о runtime нельзя менять совместимость основного приложения.
- Реальные вызовы XActions для профилей, лент, списков и участников.
- Полная end-to-end связка HTTP клиента с worker; при этом схемы курсоров и
  транзакционное сохранение публикаций готовы как изолированные строительные блоки.
- Интеграция с существующими квотами аккаунтов и реальными ограничениями X.
- Вариант `COLLECTOR_ENGINE=xactions`, UI, HTTP-поиск и исторический архив.
- Функциональные тесты против X: не выполнялись в этой ветке.

## Критические требования перед подключением к worker

1. Использовать существующий `pickAccount` и единственную аренду аккаунта.
2. Не создавать SQLite пул XActions и не сохранять расшифрованные cookies на диск.
3. При HTTP 429 останавливать запрос, передавать `Retry-After`/reset,
   не пытаться обходить ограничения перебором аккаунтов.
4. Транзакционно сохранять записи страницы, архив и `nextCursor`, соблюдая
   аренду задачи и аккаунта. Числовой `max_id` — отдельное состояние.
5. Нельзя переключать `main` или флаг `X_COLLECTOR=src` без интеграционных тестов.
