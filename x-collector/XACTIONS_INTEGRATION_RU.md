# XActions HTTP: экспериментальная локальная интеграция

Ветка: `feature/xactions-http-engine`, PR #61 (draft, **не объединять в main**).
Зафиксированный источник: `nirholas/XActions` v3.5.0, commit
`b9c4bf7bd680f82d4ede0a1b48bb1c5dbfd7bb78`.

## Статус

Реализован отдельный HTTP-путь для **profile**, **timeline**, **members** и обычных поисковых
заданий `list:<ID>` без параметров архивного/исторического сбора. Изменения
в рабочем сборщике активируются **только** через `COLLECTOR_ENGINE=xactions`.

По умолчанию весь сбор остаётся Playwright. Текстовый поиск, исторические
задания и сбор участников списков пока работают по старому пути либо ещё
не интегрированы. Режим `auto` пока не реализован.

## Новые модули

- `src/xactions/transport.ts`: SOCKS5 с жёсткой проверкой схемы прокси,
  отменой запроса, тайм-аутом, ограничением тела и отсутствием прямого fallback.
- `src/xactions/session.ts`: cookies из уже арендованной и расшифрованной
  Playwright-сессии; только домены X.
- `scripts/xactions-http-loader.cjs`: загрузка ESM библиотеки из локального
  checkout XActions с проверкой точного commit SHA.
- `src/xactions/runtime.ts`: отключены фоновое обновление query IDs,
  дополнительная подпись и автоматические повторы. Разрешены только HTTPS
  обращения к x.com, с прокси и единой отменой. Для новой библиотеки нужен
  Node.js >= 22.12; остальной сборщик сохраняет совместимость с Node 20.
- `src/xactions/engine.ts`: чтение профиля, авторской ленты, списка и страниц участников. Парсеры `userTimelineInstructions` и `parseUserList` загружаются из отдельных исходных модулей XActions.
- `src/xactions/normalize.ts`: приводит ответы к формату TweetSchema/ProfileSchema;
  отсутствие метрик, которое XActions иногда превращает в ноль, сохраняется
  консервативно как null (включая настоящий 0, если его нельзя отличить).
- `src/xactions/account-http-quota.ts`: **первый** HTTP-запрос покрывается
  предварительно списанным весом `pickAccount`. Каждый последующий запрос
  резервирует тот же вес операции (profile=1, search=3, timeline=5) в общей
  таблице `x_accounts`. При исчерпании квоты задача откладывается.
- `migrations/042_xactions_list_members.sql`: отдельная таблица наблюдений участников списков и новый тип задач `members`.
- `src/xactions/persist-members.ts`: атомарная запись профилей, принадлежности к списку и HTTP-курсора.
- `migrations/041_xactions_checkpoints.sql` и `src/xactions/checkpoint-store.ts`:
  независимые HTTP cursors и lease fencing.
- `src/xactions/persist.ts`: публикации и курсор сохраняются в **одной**
  PostgreSQL-транзакции через существующий `persistTweets`. В счётчик
  прогресса входят новые уникальные связи `x_task_tweets`, а не повторы
  одинаковых твитов на разных HTTP-страницах. Для участников аналогично
  используются новые связи `x_task_profiles`. Числовые
  `history_max_id` и `list_max_id` не заменяются HTTP курсорами.
- `src/xactions/task.ts`: маршрутизация разрешённых задач через общий worker.
- `tests/xactions-http.test.ts`, `tests/xactions-engine.test.ts`,
  `tests/xactions-runtime.test.ts`: автономные проверки без обращения к X.

## Подготовка Windows для будущих ручных тестов

Не выполняйте эти команды на рабочей копии, пока PR не пройдёт все проверки,
и предварительно сделайте резервную копию БД.

В PowerShell установите Node.js 22.12+ и Git. Затем в отдельную директорию
клонируйте XActions и переключитесь на строго проверенный коммит:

```powershell
git clone https://github.com/nirholas/XActions.git C:\\tools\\XActions
cd C:\\tools\\XActions
git checkout b9c4bf7bd680f82d4ede0a1b48bb1c5dbfd7bb78
npm ci
```

В новом терминале для X Collector (после `npm ci`, настройки локального PostgreSQL,
наличия действующих аккаунтов SOCKS5 и запуска миграции 041) включите
экспериментальный режим:

```powershell
$env:XACTIONS_ROOT = "C:\\tools\\XActions"
$env:COLLECTOR_ENGINE = "xactions"
```

Без этих двух переменных запускается прежний Playwright-парсер. Если
используются только браузерные задачи, установка XActions не нужна.
Прокси и сессии берутся из `x_accounts`, пароли в окружение не копируются.
**Ветка пока экспериментальная, делать реальные запросы к X рано.**


Для постановки отдельного задания на участников списка (после применения
миграций, только в экспериментальном режиме):

```powershell
$env:COLLECTOR_ENGINE = "xactions"
npm run xactions:members -- 1878727153048777016 100
```

Это добавляет в **локальную PostgreSQL** задачу `members`; фактический сбор
происходит при запуске worker. Нельзя запускать на рабочей базе до
контролируемых интеграционных испытаний.

Текущее состояние любого задания можно просмотреть **без изменения БД**:

```powershell
npm run xactions:status -- 1234
```

Команда показывает этап и попытки задания, количество подтверждённых страниц,
**новых уникальных** публикаций/участников и наличие курсора для продолжения.
Сами HTTP-курсоры, cookies и секреты в консоль не выводятся.
При отсутствии миграции 041 сначала требуется применить миграции локальной БД.

## Проверки

```powershell
cd x-collector
npm run typecheck
npm run lint
npm run xactions:verify  # после установки XACTIONS_ROOT, без сетевых запросов к X
node --import tsx --test tests/xactions-http.test.ts tests/xactions-engine.test.ts tests/xactions-runtime.test.ts tests/xactions-db.test.ts
npm run test
```

GitHub Actions выполняет проверку на Linux без реальных X-аккаунтов.
Локальный запуск на Windows, реальные HTTP вызовы через SOCKS5,
транзакционная проверка crash/restart и полнота данных требуют отдельного
контролируемого теста. Результат CI указан в PR, не в этом документе.

## Ограничения

- В `XActions` 3.5.0 нет гарантии стабильности приватных GraphQL endpoints.
- Не исправлен `SearchTimeline` HTTP 404; ключевые слова собираются Playwright.
- Участники списков поддержаны отдельным типом задач, но полнота списка и реальные HTTP-ответы ещё не проверены на Windows.
- Число публикаций на странице не фиксировано. Объём задания определяется
  фактически записанными элементами, а не формулой `limit/20`.
  Если защитный лимит страниц исчерпан до нужного объёма, задание
  **не помечается успешно выполненным**, а повторяется через обычную очередь
  с сохранённого курсора. При достижении целевого объёма возможен сохранённый
  курсор (это не означает, что прочитана вся история источника).
- HTTP-поиск ключевых слов остаётся выключенным. Есть только изолированный
  `diagnosticSearchPage`, проверка его переменных и offline-контроль
  `SearchTimeline=POST` через `xactions:verify`. HTTP 404 пока не устранён.
- XActions учитывает нулевой остаток квоты из `x-rate-limit-remaining` и
  `x-rate-limit-reset`, предотвращая следующий запрос до сброса лимита.
- Переход XActions без ручной проверки не включать в production.

## Исправления после второго ревью (14.10.2026)

- **P1 — конец ленты:** отсутствие `cursor-bottom` больше не считается доказательством
  конца. Требуется `TimelineTerminateTimeline`; другой ответ без курсора
  останавливается как неоднозначный. Это намеренно консервативный режим:
  если X перестанет возвращать terminal instruction, потребуется обновить
  адаптер и фикстуры, а не автоматически помечать неполную историю полной.
- **P1 — частичный сбор:** по окончании `pageBudget` с валидным сохранённым
  курсором worker вызывает `deferTask` и **возвращает попытку** в очередь.
  Частичный результат — не ошибка парсера и не повод отправлять в DLQ.
- **P1 — HTTP 403:** если нет признаков CAPTCHA/challenge, отказ доступа
  классифицируется отдельно и **не переводит** здоровый аккаунт в CAPTCHA.
  Уточнение прав доступа к защищённому источнику — отдельная задача.
- **P2 — производительность:** число новых уникальных публикаций и участников
  определяется `INSERT ... ON CONFLICT DO NOTHING` (`rowCount`) внутри
  той же транзакции, без `COUNT(*)` по всей истории задания.
- **P2 — точность профиля:** частичные HTTP-профили не сбрасывают ранее
  подтверждённое `is_verified=true` в `false`. Браузерный источник
  сохраняет прежние правила обновления.
- **P2 — квоты:** при отказе в списании HTTP-веса определяется причина:
  действующая аренда + лимит или **потеря аренды**. Повтор по причине аренды
  не объявляется исчерпанием квоты. Данные `x-rate-limit-remaining/reset`
  учитываются отдельно по GraphQL endpoint.
- **Защита от зависания:** 5 последовательных страниц без новых уникальных
  записей вызывают `XACTIONS_NO_PROGRESS`, не подтверждая конец архива.
  Ошибка не ухудшает здоровье аккаунта; обычные попытки задания ограничены.

### Ограничения

- Без авторизованного Windows + SOCKS5 испытания нельзя подтвердить
  совместимость реальных GraphQL-потоков, особенно terminal instruction.
- PostgreSQL/PGlite и GitHub Actions не заменяют долгий нагрузочный тест
  с несколькими процессами и перехватом аренды.
- `SearchTimeline` HTTP 404 по-прежнему не считается исправленным.

## Исправления после третьего ревью (14.10.2026)

- **ListTimeline**: `listPage()` теперь проходит `verifyHttpPageEnd()`, как и
  лента автора, участники списка и диагностический поиск. Курсор `null`
  без явной `TimelineTerminateTimeline` — **не доказательство конца**.
  Неподтверждённый формат считается ошибкой и не завершает историю.
- **403 неизвестной причины**: стандартный ответ XActions
  `AuthError: Authentication failed (403)` считается
  `ACCESS_UNVERIFIED`, а не постоянной блокировкой/капчей. Очередь
  повторяет задачу с ограниченным бюджетом попыток и паузой 2 минуты,
  здоровье аккаунта не ухудшается. Только явно защищённый ресурс
  классифицируется как `ACCESS_DENIED` (без гарантий, что X пришлёт
  достаточно сведений). После повторных 403 проверьте cookies и доступ
  **через интерфейс X**, не обходя защиту.
- **Миграция 043** сохраняет `consecutive_empty_pages` одновременно с
  данными и cursor. После перезапуска worker порог остановки не
  обнуляется. `xactions:status` показывает число последовательных
  страниц без новых записей.
- **Верификация с источником**: подтверждённое поле GraphQL
  `verification.verified` может принимать `true` и `false`; отсутствие
  поля трактуется как `unknown`. Неизвестное значение не изменяет
  ранее подтверждённую верификацию. Достоверность сохраняется также
  в raw observations.
- **Атомарность происхождения**: строка `archive_sources` для HTTP
  сохраняется в одной транзакции с публикациями и курсором.
  Содержимое gzip-файлов хранится в filesystem, который не является
  частью PostgreSQL-транзакции. При неуспешном COMMIT потенциально
  остаются orphan-файлы, но связанные записи БД не повреждаются.
- **Очистка сырого архива**: `npm run xactions:archive-gc` — сухой
  просмотр. `npm run xactions:archive-gc -- --delete` явно удаляет
  только raw-гzip файлы старше **24 часов**, которые не имеют ссылок
  в `archive_raw_pages`. Состояние БД проверяется ещё раз перед
  удалением. Это решение для локального ноутбука, не фоновая служба.
- **Тесты**: добавлены SQL/PGlite тест на сохранение no-progress streak
  при смене lease, тест GC и интеграционный тест реальной PostgreSQL
  очереди `claim → partial → defer → claim → done` (временная схема,
  без обращения к X).

### Оставшиеся условия перед включением в основной сбор

1. В собственном Windows-окружении сверить с реальными ответами X формы
   терминальных инструкций. Из-за строгой защиты не все корректные
   варианты окончания могут распознаваться; это безопаснее ложной полноты.
2. Проверить авторизованный SOCKS5, ограничения и восстановление с
   живыми процессами и локальной PostgreSQL.
3. HTTP SearchTimeline 404 не признан исправленным. До проверки
   ключевые запросы остаются на Playwright.

### Подготовка к объединению (14.10.2026)

Загрузчик CJS включён в сборку. CI после сборки проверяет импорт
скомпилированного collector runtime без внешнего SDK и сетевых запросов.
HTTP transport ограничивает полное время запроса, включая подключение
к SOCKS5 и непрерывную медленную передачу. Локальные сетевые тесты
проверяют общий тайм-аут, обычный ответ и отмену запроса.

Объединение добавляет экспериментальный метод; включение в рабочем
окружении — отдельный этап после проверок выше. По умолчанию остаётся
Playwright. Автоматические задания трёх списков, история и тематический
поиск сохраняют текущий маршрут; автоматического HTTP → Playwright
fallback нет. Для отката выбора метода верните `COLLECTOR_ENGINE=playwright`
и перезапустите worker. Дополнительные таблицы и собранные данные сохраняйте.

Локально: 46 XActions-тестов прошли, проверены типы, сборка и импорт
собранного runtime. Полная регрессия и PostgreSQL-интеграция проверяются
GitHub Actions для итогового commit. Живые запросы к X здесь не выполнялись.
