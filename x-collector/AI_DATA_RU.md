# Подготовка базы для ИИ и ускорение записи

Добавлена миграция 018_ai_foundation.sql. Применяйте сначала на отдельной тестовой базе. На существующей большой базе создание индексов может блокировать запись: выбирайте окно обслуживания и делайте резервную копию.

Архив записывается пакетами по типу сущности вместо запросов на каждый твит. Сохраняются транзакции, NULL для неизвестных счётчиков, происхождение, связи, история метрик и исходные файлы. Регистрация источника вынесена из внутреннего цикла пакетов.

Контрольный тест 200 постов: минимальная прежняя построчная запись выполняет 403 SQL-запроса; новая запись вместе с историей текстов — 6. При пользователях/связях добавляется до трёх пакетных запросов. На PGlite в отдельном прогоне измерено 183,5 мс против 23,2 мс. Это измерение тестовой базы, не обещание скорости X: сеть, ограничения платформы, диск и PostgreSQL влияют на результат. Параллелизм браузера и ограничения X не увеличены.

## Структура

- archive_post_versions: неизменяемая версия текста/автора/языка с временем получения, источником и SHA-256 исходного файла.
- ai_models: имя, неизменяемая версия, назначение, размерность и конфигурация модели.
- ai_post_results: результат обработки конкретной версии текста, хеш текста, версия модели и необязательный embedding. Повтор идентичного результата идемпотентен; изменение требует новой версии модели. Неподходящая размерность и несовпадающий хеш отклоняются.
- Индексы для выбора версий и метрик на исторический момент.

Готовые нейросети не подключены и случайные embeddings не создаются. PostgreSQL хранит векторы в массиве float8; индексированного семантического поиска сейчас нет. pgvector можно добавить отдельной миграцией после выбора модели/размерности и проверки доступности расширения.

## Выгрузка JSONL для признаков

Из папки x-collector, после настройки DATABASE_URL и миграций:

```powershell
node --import tsx scripts/ai/export.ts --from 2024-10-08T00:00:00+03:00 --to 2026-10-09T00:00:00+03:00 --as-of 2026-10-08T04:00:00+03:00 > ai-input.jsonl
```

Можно использовать npm run ai:export -- с теми же параметрами, но для перенаправления чистого JSONL запускайте node напрямую: npm печатает служебный заголовок. В Windows PowerShell 5.1 перенаправление обычно создаёт UTF-16; при передаче в Python укажите encoding='utf-16' или конвертируйте файл в UTF-8. В PowerShell 7 используйте его UTF-8 вывод.

Время --to исключительное. --as-of ограничивает и время наблюдения метрик, и время их получения. Текст выбирается из сохранённой к этому моменту версии. Изменения и метрики, полученные после отсечки, исключены. Отсутствующие счётчики остаются NULL. Числа bigint выводятся строками без потери точности. Выгрузка читает не более 500 кандидатов за раз (настраивается --batch от 1 до 1000), поддерживает обратное давление stdout.

Старые строки без сохранённых версий не выгружаются: прошлые тексты не восстанавливаются выдуманным задним числом. При старте после миграции версии появятся при следующем фактическом сборе. История профилей и браузерных сущностей остаётся в существующих таблицах; в эту выгрузку они пока не включены. Метки будущей доходности токенов не подмешиваются в признаки. Совпадение автора/токена не доказывает общего владельца.

## Продолжение

Выберите задачу/модель (тематика, sentiment, embeddings); подключите реальный провайдер отдельным worker. lib/ai/data.ts предоставляет registerModel и saveResult. Сейчас saveResult проверяет SHA-256 текста: этот контракт предназначен для анализа текста. Для модели с метриками/графом нужно расширить контракт хешем полного набора признаков и закрепить feature_as_of. Платные вызовы и обучение автоматически не запускаются.
