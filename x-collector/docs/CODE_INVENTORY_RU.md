# Аудит потенциально неиспользуемого кода

Knip используется только как **диагностический** инструмент. Его результат
не является разрешением на удаление файла.

## Точки входа

Все `scripts/` считаются потенциальными ручными CLI-точками входа, а все
тесты перечислены отдельно. Это снижает число ложных срабатываний для
скриптов, которые запускаются напрямую, а не через `package.json`.

## Правило удаления

Удалять модуль можно только после:
1. результата Knip;
2. проверки статических импортов;
3. проверки динамических `require/createRequire/import()`;
4. проверки `npm run`, cron/Task Scheduler и внешних CLI;
5. полного typecheck/lint/build/test.

Похожие имена файлов не считаются доказательством дублирования.

Текущая ветка намеренно не удаляет 100+ файлов intelligence. Сначала
составляется список кандидатов, затем каждый набор удалений идёт отдельным
маленьким PR.
