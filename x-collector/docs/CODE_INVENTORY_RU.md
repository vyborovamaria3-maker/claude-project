# Проверка использования кода X Collector

Цель: находить **кандидатов на удаление**, а не стирать функциональность по
похожим именам файлов. Работа отдельно от PR про PostgreSQL и миграции.

## Факты о текущей основной ветке

На момент проверки в `main`:
- в `lib/intelligence/` 163 отслеживаемых файла, а не 210;
- тестов 61 файл (58 в корне `tests`, 3 в `tests/integration`);
- совпадает только базовое имя `graph-monitoring.test.ts`;
- в `scripts/` 91 отслеживаемый файл;
- большинство файлов intelligence существовали до PR #69 и **не**
  являются добавлениями этого PR.

Файлы `entity-discovery.ts` и `entity-resolution.ts` реализуют
разную глубину функциональности. Похожие названия двух файлов сами по
себе не доказывают дублирования. Нужно изучить вызовы и контракты.

## Запуск Knip (не изменяет код)

Из `x-collector` на ноутбуке с Node.js >=20.19:

```powershell
npm ci
npm run audit:unused
```

Команда фиксирует Knip 6.41.0 в разовом `npm exec` и печатает JSON.
Первый запуск потребует доступ в npm registry, исходники не меняются.
Непустой отчёт Knip обычно завершает команду с кодом 1; это
диагностический результат, а не ошибка сборки.

`knip.jsonc` содержит все `scripts/` как потенциальные точные
точки входа: некоторые выполняются вручную и не перечислены в
`package.json`. Тесты включены отдельно. Поэтому будут видны
в первую очередь **неиспользуемые файлы и экспорты**, а не подозрения
на удалённые вручную CLI-команды.

Ограничение: динамические `require()`, `createRequire(__filename)`,
плагины и имена, формируемые во время выполнения, Knip может не
распознать. Задания cron и Windows Task Scheduler также не видны ему.
**Никакого автоматического `--fix` или `--allow-remove-files`.**

## Критерии фактического удаления

1. Результат Knip + поиск всех статических и динамических ссылок.
2. Отсутствие вызывающих команд `npm scripts`, ручных CLI-операций,
   тестов, HTTP-маршрутов, миграций или архивных reader'ов.
3. Нет зависимостей API, обрабатывающих сохранённые данные старых версий.
4. Сфокусированный PR и полный зелёный CI (typecheck, lint, build,
   тесты с PostgreSQL, контроль XActions).
5. При необходимости сохранён совместимый импорт для внешних сценариев.

## Разделение долгой чистки на независимые PR

- Миграционный инвентарь и запрет неявного SQL — отдельно.
- Архивные отчёты из корня — отдельно.
- Анализ импорта (этот PR) — отдельно.
- Перенос `lib/trade/analytics-*.ts` в `intelligence/` —
  только после карты обратных зависимостей.
- `scripts/setup/`, `scripts/manual-tests/`, `scripts/ops/` —
  после проверки относительных путей и `npm run` команд.
- Слияние похожих intelligence-модулей — последними, по проверенным
  функциям, контрактам и fixture-тестам. Не целиться в произвольное
  число 300 файлов.

Оригинальный X Collector проверяется через Playwright и XActions.
MTProto относится к Telegram и не является его частью.
