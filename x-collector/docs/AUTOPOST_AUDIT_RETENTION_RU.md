# Autopost v2 — хранение аудита и восстановление

**Статус: применяемая политика для V2-01.** Дата решения: 2026-10-19. Система запускается локально на ноутбуке; PostgreSQL — источник истины.

## 1. Минимальные гарантии

- `xc_auto_job_events` — append-only журнал. SQL-триггеры запрещают `UPDATE`, `DELETE` и `TRUNCATE`; события не «чистятся» автоматически.
- `xc_auto_job_attempts` — редактируемая сводка каждой попытки, но уникальная пара `(job_id,attempt_no)` предотвращает смешение попыток. Связанные события должны переживать любые повторные проверки.
- `xc_auto_jobs` и `xc_auto_reconcile` — текущие состояния, а не самостоятельная замена истории; события и попытки имеют внешние ключи `ON DELETE RESTRICT` к заданиям. Удаление job с историей запрещено схемой.
- В аудит передаются только разрешённые технические значения: статус, тип действия, время, категории/коды ошибок, идентификатор попытки, `trace_id`, число проверок. Полный текст твита, cookies, секреты, raw body X, прокси и произвольные exception.message не включать.
- Для старых заданий, существовавших до установки V2-01, история **не восстанавливается задним числом**. Не делать фиктивные события.

## 2. Срок хранения и действия оператора

**По умолчанию история сохраняется бессрочно до отдельного подтверждённого архивирования.** Автоматическое удаление аудита в текущей версии выключено и не планируется запускаться фоновым Worker. Это безопаснее потери доказательств неопределённой публикации.

Раз в **90 дней** рекомендуется проверить объём аудита и свободное место на диске с PostgreSQL. Период **180 дней** — минимальный рекомендуемый горизонт первичного расследования, не TTL и не команда SQL `DELETE`.

Если объём требует сокращения, сначала спроектировать и проверить в отдельном PR ручную последовательность: остановить publisher Worker; сделать консистентный backup; выгрузить и проверить jobs/attempts/events с контрольными суммами; исключить `running`, `uncertain`, `manual_review` и `manual_required`; провести тест восстановления в другой базе; получить явное разрешение оператора; только потом выполнить проверяемую транзакционную миграцию/архивацию в тестовой среде. **В текущем V2-01 механизма удаления аудита нет.**

Ни одна функция настройки/UI и никакая команда с именем `audit` не должна удалять историю. Для выгрузки использовать доступ только к чтению.

## 3. Проверка без изменений БД

В отдельном SQL-клиенте под read-only ролью:

```sql
SELECT count(*) AS events, min(occurred_at) AS oldest_event_ms, max(occurred_at) AS newest_event_ms
FROM xc_auto_job_events;

SELECT count(*) AS attempts, min(started_at) AS oldest_attempt_ms
FROM xc_auto_job_attempts;

SELECT pg_size_pretty(pg_total_relation_size('xc_auto_job_events')) AS events_disk,
       pg_size_pretty(pg_total_relation_size('xc_auto_job_attempts')) AS attempts_disk;

SELECT count(*) AS unresolved
FROM xc_auto_jobs WHERE status IN ('running','uncertain');
```

Эти запросы работают с уже установленной v2-схемой, только читают данные, не создают задания и не обращаются к X.

## 4. Резервное копирование и локальная эксплуатация

- До `node scripts/setup-autopost.cjs` создать подтверждённую резервную копию текущей PostgreSQL. SQL-скрипт обновляет схему и триггеры, но не должен запускаться без плана восстановления данных.
- Регулярные backup-файлы сохранять **вне Git**; защищать паролями/шифрованием и правами файловой системы. Не загружать дампы в PR или диагностические логи.
- Периодически проверять восстановление в одноразовую тестовую БД; только существование файла бэкапа недостаточно.
- Ошибки диска или недоступности БД должны останавливать запись нового аудита/переходов, а не тихо обходить журнал. Если X-действие уже могло произойти, повтор запрещён независимо от доступности БД.

## 5. Будущие изменения

Удаление/компактизация могут появиться **только отдельным PR** с реальным cold archive, доказуемым восстановлением, защитой незавершённых заданий, retention-метриками и пользовательским подтверждением. Не отключать append-only триггер из обычного Worker и не добавлять `ON DELETE CASCADE` для удобства очистки.
