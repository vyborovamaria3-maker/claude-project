# Аудит миграций X Collector

## Почему старые номера не следует просто переименовывать

Изначально в `migrations/` накопились несколько SQL-файлов с номерами
`012`, `013`, `014` и `036`. Это **не** означает случайного порядка
применения: рабочий мигратор (`scripts/migrate.ts`) проходит явный
`REQUIRED` из `lib/trade/migrations.ts` и хранит полное исходное
имя применённого файла в `schema_migrations(filename)`.

Переименование файла `012_reply_guy.sql` без миграции реестра приведёт
к тому, что уже инициализированная БД посчитает новое имя неприменённым.
Повторное выполнение DDL может вызвать конфликт или порчу состояния.
Поэтому исторические имена и порядок **заморожены**. Долговременное
упорядочивание следует делать отдельным проектом с поддержкой обновления
существующей БД и тестами на чистую/частично мигрированную БД.

## Что контролирует новая проверка

`npm run migrate:audit` безопасно читает файлы и печатает JSON-отчёт.
Она не подключается к PostgreSQL и не применяет SQL. Проверяются:

- все файлы из `REQUIRED` существуют;
- каждый SQL-файл либо включён в `REQUIRED`, либо явно указан в
  `EXCLUDED_MIGRATIONS` с причиной;
- новых коллизий номеров нет; старые четыре группы задокументированы;
- имена и записи списка уникальны;
- неизвестные SQL-файлы блокируют `npm run migrate` до экспертизы.

Сам `migrate` делает этот аудит **до открытия соединения с БД**.
Имеющаяся таблица `schema_migrations` и логика транзакционного
применения + advisory lock не изменены.

## Восемь SQL, не включённых в текущую цепочку

`012_ai_reply_guy.sql` — альтернативная схема аккаунтов и Reply Guy,
потенциальный конфликт с действующим `012_reply_guy.sql`.

`025_intelligence_identity_resolution.sql`,
`026_intelligence_tags_v2.sql`, `027_intelligence_scores.sql`,
`028_intelligence_graph_timeline.sql` — неадаптированные расширения
моделей intelligence; требуют проверки совместимости.

`030_intelligence_jobs.sql`, `031_intelligence_graph_analytics.sql`
— в этих файлах используются BIGINT-ссылки на `ip_entities.id`,
тогда как текущая схема использует UUID. Включать автоматически нельзя.

`036_tweet_entities.sql` — альтернативное хранилище сущностей публикаций;
перед переносом данных необходимо сопоставить с `twitter_entity_links`.

**Исключённые файлы не удалены и не включены в рабочую цепочку.**
Новым разработчикам нельзя запускать весь каталог миграций по алфавиту.

## Проверка

Из корня `x-collector`:

```powershell
npm run migrate:audit
npm run typecheck
npm run lint
npm test
npm run build
```

Интеграционный тест `tests/migrations.test.ts` прогоняет рабочий
`REQUIRED` на одноразовом PostgreSQL-движке. Новые тесты каталога
проверяют, что неизвестный SQL, новая коллизия и пропущенный файл
обнаруживаются до подключения к БД. Тесты не подтверждают миграцию
конкретной пользовательской базы — для этого нужна отдельная копия.
