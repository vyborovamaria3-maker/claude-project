# Аудит миграций X Collector

## Правило

Порядок применения SQL задаётся только `lib/trade/migrations.ts` и сохраняемым
именем в `schema_migrations`. Исторические коллизии номеров `012`, `013`,
`014` и `036` не переименовываются автоматически: существующая БД уже
может содержать эти имена. Переименование без совместимого перехода может
заставить старую БД повторно выполнить DDL.

В каталоге также есть восемь SQL-файлов, которые намеренно не входят в
`REQUIRED`. Они явно перечислены в `EXCLUDED_MIGRATIONS` с причиной.
Это предотвращает случайный запуск SQL «просто потому, что файл лежит в
migrations/`.

## Контроль

`npm run migrate:audit` выполняет файловый preflight без подключения к
PostgreSQL. Обычный `npm run migrate` выполняет тот же preflight **до**
создания Pool.

Добавление нового SQL требует сначала добавить его в явный manifest либо
в список исключений с обоснованием. Неизвестный SQL блокирует мигратор.

## Безопасное упорядочивание в будущем

Если потребуется перейти на монотонные номера, сначала нужна отдельная
совместимая миграция/реестр с тестами для существующих production БД.
Исторические файлы нельзя просто переименовать и считать проблему решённой.

## Контроль checksum и migration drift

Мигратор сохраняет SHA-256 точного SQL-текста для каждой новой применённой миграции. При следующем запуске все записи `schema_migrations` сверяются с файлами из `migrations/`; изменённый SQL, отсутствующий файл или несовпадение checksum блокирует применение новых миграций.

Для существующей БД старый ledger может не содержать checksum. После проверки актуальных SQL-файлов и создания резервной копии один раз запускается `npm run migrate -- --baseline-checksums`. Эта команда фиксирует текущие файлы только для уже применённых строк, проверяет результат и завершает работу **без применения ожидающих миграций**. После этого обычный `npm run migrate` проверяет checksum и продолжает цепочку.

Важно: первоначальный baseline доверяет текущему содержимому уже применённых SQL и не может выявить изменения, сделанные до включения checksum-защиты. Если checksum уже есть и не совпадает с файлом, baseline не перезаписывает её и мигратор завершается с ошибкой. `npm run migrate -- --status` показывает `baseline required` для старых записей без checksum и выявляет уже известный drift.
