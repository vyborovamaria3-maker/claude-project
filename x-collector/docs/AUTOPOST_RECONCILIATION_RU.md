# X autopost: сверка неопределённых отправок

## Обновление схемы

После получения изменений из ветки запустите из каталога **x-collector**:

    node scripts/setup-autopost.cjs

Скрипт читает локальный .env, подключается к PostgreSQL и применяет идемпотентную схему из scripts/autopost/schema.sql. Он не отправляет посты в X. Убедитесь, что DATABASE_URL и MASTER_KEY настроены так же, как для остальных процессов коллектора.

Затем перезапустите существующий autopost worker:

    node scripts/autopost-worker.cjs

Если worker управляется вашим локальным процесс-менеджером, перезапустите его обычным способом вместо запуска второго экземпляра. Worker использует PostgreSQL advisory lock, поэтому параллельный второй экземпляр не должен обслуживать эту очередь.

## Как работает сверка

Когда действие уже перешло через границу отправки, но X не подтвердил результат, задание остаётся в состоянии **uncertain**. Оно не отправляется повторно автоматически.

Для публикаций и ответов создаётся запись в таблице xc_auto_reconcile:

- первая проверка — примерно через минуту;
- затем проверки повторяются с увеличивающимися интервалами;
- поиск использует username, полный текст с раскрытыми ссылками и время рядом с моментом отправки;
- единственное точное совпадение переводит задание в **published** и сохраняет найденный пост;
- несколько совпадений переводят сверку в **manual_review**;
- если к пределу в 24 часа точное совпадение не найдено, статус становится **manual_required**;
- если сессия, прокси или доступ к X не позволяют безопасно выполнить проверку, сверка останавливается для ручного решения.

Неопределённый результат никогда не считается доказательством того, что публикации не было. Отсутствие совпадения в ленте также не доказывает отсутствие поста — поэтому автоматического повтора по таймауту нет.

Автоматическая сверка поддерживает **post** и **reply**. Неопределённые **like**, **repost** и **follow** переходят в ручную проверку: для них автоматическое подтверждение этим спринтом не реализовано.

## Ручное решение

Команды выполняются через существующий IPC-конвейер scripts/autopost/engine.cjs; это не новые публичные HTTP endpoints.

### Подтвердить найденную публикацию

Отправьте команду с UUID задания и ID найденного поста:

    {
      "action": "reconcile-confirm",
      "id": "<UUID задания>",
      "tweet_id": "<ID найденного поста>"
    }

Если список кандидатов пуст и оператор нашёл пост вручную, добавьте поле "manual_confirm": true. Для неоднозначного результата с кандидатами разрешается выбрать только ID из списка.

### Разрешить повторную отправку

Только после ручной проверки X и подтверждения, что публикации действительно нет:

    {
      "action": "reconcile-retry",
      "id": "<UUID задания>",
      "confirmed_not_published": true
    }

Задание возвращается в очередь; дальше действуют обычные настройки паузы, аккаунта и расписания. Не используйте эту команду, если результат всё ещё неоднозначен.

## Наблюдение

Команда overview возвращает активные записи сверки в поле reconciliation. Основная запись задания находится в xc_auto_jobs, а найденные кандидаты и причина ручного решения — в xc_auto_reconcile.

Текущая проверка не использует живой X-аккаунт и не отправляет тестовые публикации. Перед включением на рабочем аккаунте проверьте миграцию, статус worker и наличие записи сверки в тестовом окружении.
