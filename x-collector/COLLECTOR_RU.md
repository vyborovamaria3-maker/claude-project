# Существующий сборщик X

Сохранена архитектура scheduler → x_tasks → worker → Playwright → PostgreSQL.
Search, timeline и profile используют имеющуюся зашифрованную сессию. CAPTCHA, истёкшая сессия и rate limit останавливают сбор, в том числе при прокрутке. Обход ограничений не добавлен.

## Исправления

Основная ссылка определяется по time основного поста, а не по первой ссылке /status/. Сохраняются media-only публикации; учитываются активные unlike/unretweet кнопки и aria-label счётчиков. Недоступные метрики возвращаются NULL. Компактные числа приблизительны; исходный снимок отражает видимый DOM, не официальный точный счётчик.

В worker сохранение вынесено в lib/trade/collector-store.ts. Одна транзакция сохраняет текущую запись, снимок наблюдения, сущности, архив и существующие mint-связи. Снижение счётчика сохраняется; время наблюдения защищает текущую запись от более старого результата. Дубликаты одного поста в порции исключаются. Профили получают историю JSON-снимков; текущий verified больше не остаётся навсегда true.

Migration 015 снимает NOT NULL/default 0 со счётчиков, добавляет twitter_tweet_observations, twitter_profile_observations и twitter_entity_links. Индексы позволяют искать посты по mention_handle/hashtag/url/visible_post_reference/media_photo/media_video. Старые нули не исправляются задним числом. Исходный материал также хранится сжатым в ARCHIVE_RAW_DIR; каталог и БД нужно резервировать вместе.

Ссылки на другие публикации означают visible_post_reference: DOM не всегда позволяет достоверно отличить ответ от цитаты. Упоминания связываются по handle, не по выдуманному user ID. Отсутствующая дата поста не выводится из ID: такой пост сохраняется в legacy-таблице и снимках, но не передаётся в архив, требующий дату. Текстовые ссылки могут оставаться t.co; файлы фото/видео не скачиваются. DOM виртуализирован и изменяется: сбор не доказывает полноту всего X, списков лайкнувших или подписчиков.

## Запуск

В папке x-collector установите зависимости и браузер: npm ci, npx playwright install chromium. Настройте существующие DATABASE_URL и зашифрованную сессию через штатные инструменты проекта. Проверьте npm run migrate -- --status, сделайте резервную копию и примените npm run migrate в собственной collector-базе. Затем используйте существующие scheduler/worker команды README. Для больших таблиц ALTER требует окно обслуживания; production база при разработке не изменялась.

Live X сбор не запускался: рабочей пользовательской сессии здесь нет. Тесты используют контролируемую HTML-страницу Chromium, производственное сохранение на PostgreSQL-совместимом движке и интеграцию PostgreSQL 16 в CI.

## Кнопка запуска

После получения ветки PR выполните в x-collector:

```bash
npm ci
npm run install-browser
# Настройте DATABASE_URL и постоянный MASTER_KEY в своей .env.
npm run migrate -- --status
# После резервной копии и выбора окна обслуживания:
npm run migrate
npm run login -- main
npm start
```

Откройте **http://127.0.0.1:3001/collector**. Экран проверяет соединение, таблицы/lease-колонки, расшифровку сессии и наличие auth-cookie, свободный диск, браузер и worker. Это структурная проверка сессии: действительность определяет первый запрос к X. Укажите запрос, максимум постов и нажмите «Начать парсинг». Доступны также лента и профиль аккаунта. Migration 016 связывает задание с действительно сохранёнными результатами; количество не берётся из общей таблицы.

Без активного worker dashboard запускает один локальный процесс и ждёт подтверждения регистрации. Повторная отправка одного requestId не создаёт второе задание. POST защищён авторизацией dashboard и Origin; секреты не возвращаются клиенту. Для внешних workers установите COLLECTOR_AUTOSTART=false. При закрытии dashboard его worker получает SIGTERM, браузерная операция отменяется, незавершённое задание возвращается в очередь. Внешние workers не останавливаются.

После CAPTCHA аккаунт не возвращается в работу по таймеру: пройдите ручную проверку и обновите login. Cooldown/исчерпание квоты означает ожидание доступного аккаунта, а не завершённый сбор. Установку базы и первоначальный вход нельзя заменить нажатием кнопки; пароли/cookies в форму dashboard вводить не нужно. В Docker требуются Chromium и его системные библиотеки: образ Reply API сам браузер не устанавливает.

Если worker перестал отвечать, появится «Возобновить обработку»: запускается обработчик уже существующего задания, без дубликата. Захваченное задание ждёт истечения lease; завершённые задания не повторяются этой кнопкой.
