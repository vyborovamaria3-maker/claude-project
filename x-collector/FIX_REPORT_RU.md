# Итог исправлений доступного снимка проекта

## Коротко

Подготовлена исправленная копия доступных исходников в `fixed_project/`; оригинал `project_extract/` не изменён. В копии исправлены проблемы очередей, worker/account leases, доставки outbox, обработки сессий, метрик, dashboard и social-attention аналитики. Добавлена миграция `011_runtime_hardening.sql` и ручной producer задач поиска `scripts/enqueue-search.ts`.

**Это не подтверждённая production-сборка:** предоставленный набор неполный — нет `migrations/003`, package manifest, tsconfig, тестов и deploy-конфигурации. Миграции к базе данных не применялись.

## Что изменено

- **Очереди и workers:** возврат задач с истёкшими lease, defer при отсутствии аккаунта, один claim-задача на worker, ограничение одновременного использования X-аккаунта владельцем lease, heartbeat и условное освобождение lease. Просроченный worker не должен освободить аккаунт, уже захваченный другим.
- **Outbox и уведомления:** атомарный claim, lease, повторные попытки с backoff и dead-letter после лимита; сообщения подтверждаются только если хотя бы один включённый канал доставил уведомление. Если каналов нет или все включённые завершились ошибкой, publisher не подтверждает сообщение. При частичном успехе неудачный канал записывается в лог, успешная доставка не дублируется намеренным retry. Возможна обычная at-least-once повторная доставка, если процесс упадёт после отправки, но до ack.
- **Секреты:** plaintext-файл состояния браузера больше не создаётся; сессия обрабатывается в памяти и хранится в БД в зашифрованном виде. Добавлено зануление временного plaintext Buffer.
- **Сеть/доступ:** dashboard по умолчанию слушает loopback; для внешнего bind требуется Basic Auth. Worker metrics также по умолчанию доступны только на loopback; внешний bind требует Basic Auth. Basic Auth сам по себе не шифрует HTTP — при внешнем доступе нужен TLS reverse proxy.
- **Сбор данных:** исправлены parsing чисел и передача `source_query`; добавлен CLI для ручной постановки search-задачи:
  `npx ts-node scripts/enqueue-search.ts "query" [--limit 50] [--sort latest|top] [--mint ADDRESS] [--priority 0]`.
- **Метрики и аналитика:** добавлены производители 1h/1w и daily-author метрик, исправлен rebuild кластеров, безопаснее обрабатываются MV refresh и retention. Retention использует allow-list, лимит batch и защиту от некорректного срока; записи с `archive_to_s3=true` не удаляются, пока S3-архиватор не реализован.
- **Backtest и ML:** новые прогоны используют исторические signal/attention snapshots. Метрика — изменение просмотров только собранного набора постов; это не все просмотры X, не цена токена и не торговый P&L. Комиссии для этого proxy отклоняются. ML labels строятся только из наблюдавшихся snapshots с `label_basis = 'observed_dataset_views'`; старые labels не переинтерпретируются и snapshots задним числом не выдумываются. Features фиксируются вместе с сигналом.
- **Scheduler:** агрегаты и snapshots собираются последовательно; signal/attention history начинается только после установки миграции и запуска scheduler. У старых периодов нет искусственно восстановленной истории.

## Проверки, которые удалось выполнить

- Все доступные SQL-миграции разобраны PostgreSQL-грамматическим парсером `pglast`; тела 48 PL/pgSQL-функций разобраны, 4 trigger-функции пропущены из-за ограничения parser на псевдозаписи `NEW`/`OLD`.
- Полная статическая проверка TypeScript выполнена для 28 файлов временным `tsc` 5.9 с установленными временно типами зависимостей; ошибок типов нет. Отдельная транспиляция всех 28 файлов также прошла.
- Во время проверки найдены и исправлены лишние скобки в расчёте accuracy внутри logistic-regression функции и синтаксическая ошибка Vue/JS-шаблона в dashboard.

## Что не проверено и что нужно сделать перед запуском

1. **Нет полной репозитории и миграции `003`.** Нельзя подтвердить, что предоставленный набор содержит все исходники, схему, конфиги и зависимости. Проверьте изменения на полной копии проекта.
2. **База не запускалась.** SQL parser не проверяет наличие всех таблиц/колонок в реальной базе, права, расширения, runtime-план запросов или успешное выполнение миграций. Сначала восстановите полный миграционный chain и примените его на disposable-копии БД.
3. **Нет package manifest/tsconfig/тестов.** TypeScript проверен с временными зависимостями и типовыми опциями, но официальную команду сборки и тестовый suite запустить было невозможно.
4. Перед production остановите scheduler/workers, проверьте резервную копию и политику retention, затем применяйте миграции по порядку. `011_runtime_hardening.sql` должен быть успешно применён **до** запуска обновлённых scheduler/worker. Не запускайте его на production вслепую без полного миграционного chain.
5. Политика `twitter_tweets.archive_to_s3=true` теперь безопасно пропускает destructive retention, потому что S3-архиватор в доступном коде не найден. Чтобы удаление заработало, сначала реализуйте/проверьте архивирование или осознанно поменяйте политику.
6. `enqueue-search.ts` ставит ручные X-поиски в очередь; он не заменяет отсутствующий автоматический Solana mint-discovery/feed provider. Для полноценного финансового backtest нужны исторические цены токенов — в доступном наборе их нет.
