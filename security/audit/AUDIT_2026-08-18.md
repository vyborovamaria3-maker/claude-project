# Security audit — 2026-08-18

## Findings

### SEC-001 — P0 Critical — Failed Solana transaction could satisfy legacy payment verifier

**Affected:** `solana-subscription-service/apps/api/src/services/solana.service.ts`

The verifier checked confirmation state and parsed the intended transfer/memo but did not reject RPC transaction errors. A failed on-chain transaction could therefore retain enough intent data to reach payment checks.

**Status:** FIXED

**Fix:** reject both signature-status errors and parsed transaction `meta.err` before payment-content validation. Regression tests cover both failure paths.

---

### SEC-002 — P0 Critical — Concurrent payment confirmation race

**Affected:** `solana-subscription-service/apps/api/src/services/subscription.service.ts`

Two concurrent confirmation attempts could pass the initial PENDING check before either update committed. The flow also did not cleanly extend an existing active subscription.

**Status:** FIXED

**Fix:** atomically claim exactly one PENDING payment inside the database transaction, reject subsequent claims, and extend the latest active entitlement from its existing future expiry.

---

### SEC-003 — P1 High — Telegram Mini App replay window not enforced in legacy subscription service

**Affected:** `solana-subscription-service/apps/api/src/security/telegram.ts`

Telegram Mini App data was signature-checked but did not enforce `auth_date` freshness.

**Status:** FIXED

**Fix:** 24-hour maximum age, five-minute future skew bound, numeric positive user-id validation and invalid-user JSON handling. Regression tests cover fresh, expired and future-dated sessions.

---

### SEC-004 — P1 High — Legacy Mini App BOLA / Telegram impersonation

**Affected:** `telegram-miniapp/backend-new/src/controllers/subscriptionController.ts`

Payment creation trusted a client-supplied Telegram ID; subscription status accepted arbitrary `userId` query values.

**Status:** FIXED

**Fix:** both operations derive identity from server-verified Telegram Mini App `initData`; status is limited to the authenticated user and sensitive responses are marked `no-store`.

---

### SEC-005 — P1 High — Helius webhook authentication could fail open

**Affected:** `solana-subscription-service/apps/api/src/routes/webhook.routes.ts`

When `HELIUS_WEBHOOK_AUTH_TOKEN` was empty, the route skipped authentication.

**Status:** FIXED

**Fix:** missing token now disables the webhook with 503; configured tokens are always required and compared in constant time. Input array and signature lengths are bounded.

---

### SEC-006 — P1 High — Production backend configuration could start with debug/internal-auth weaknesses

**Affected:** `solana-launcher/backend/app/core/config.py`

Production validation did not explicitly reject `DEBUG=true`, wildcard CORS, or a missing/short internal `BACKEND_API_KEY`.

**Status:** FIXED

**Fix:** production startup now fails closed for these settings. Tests cover the new policy.

---

### SEC-007 — P2 Medium — Refresh cookie could remain non-Secure after production misconfiguration

**Affected:** `solana-subscription-service/apps/api/src/config/env.ts`

`COOKIE_SECURE` defaulted to false.

**Status:** FIXED

**Fix:** production always sets the authentication cookie `Secure`, independent of the optional development override.

---

### SEC-008 — P2 Medium — JWT verification algorithm was not explicitly pinned

**Affected:** `solana-subscription-service/apps/api/src/security/tokens.ts`

**Status:** FIXED

**Fix:** signing and verification now explicitly use HS256, and access/refresh secrets must be distinct.

---

### SEC-009 — P1 High — Fixed SOL/USD quote could undercharge USDC checkout

**Affected:** `solana-subscription-service/apps/api/src/services/subscription.service.ts`

The legacy service converted SOL-denominated plan prices using a hardcoded `$150/SOL` demonstration value.

**Status:** MITIGATED / FIXED FOR PRODUCTION

**Fix:** production USDC checkout now fails closed until a live price oracle is configured. Development retains the deterministic demo quote.

---

### SEC-010 — P2 Medium — Mutable GitHub Action references

**Affected:** `.github/workflows/repository-hygiene.yml`

The workflow used moving action tags while the repository's own security regression requires immutable action SHAs.

**Status:** FIXED

**Fix:** checkout and setup-node are pinned to immutable 40-character commit SHAs.

---

### SEC-011 — P2 Medium — Legacy Mini App HTTP hardening gaps

**Affected:** `telegram-miniapp/backend-new/src/index.ts`, `src/config/index.ts`

The legacy backend exposed the Express technology header, accepted unbounded JSON, lacked baseline browser security headers, and had weak production configuration validation.

**Status:** FIXED

**Fix:** disabled `X-Powered-By`, bounded JSON at 256 KiB, added baseline headers, validated ports/URLs/secrets and require HTTPS frontend in production.

---

### SEC-012 — P0 Critical — Telegram bot credential committed in source and git history

**Affected current paths before remediation:** `telegram-miniapp/bot/bot.ts`, `telegram-miniapp/bot/bot.js`, `telegram-miniapp/bot/set-menu-button.js`.

A live-format Telegram bot credential was embedded directly in tracked source and is also present in repository history. The credential value is intentionally omitted from all audit documentation.

**Status:** CURRENT SOURCE FIXED — PROVIDER-SIDE ROTATION REQUIRED

**Fix applied:** removed every hardcoded fallback credential from the current bot sources, require `BOT_TOKEN`/`WEBAPP_URL` at runtime, added a safe `.env.example`, and added a redacted current/diff secret gate.

**Closure requirement:** revoke/regenerate the exposed bot credential at Telegram, update the deployment secret store, redeploy, and verify the old credential no longer authenticates. History rewriting is optional defense in depth after rotation; it is not a substitute for rotation.

---

### SEC-013 — P0 Critical — External API credential embedded in `.editorconfig`

**Affected current path before remediation:** `solana-launcher/.editorconfig`.

The file contained unrelated provider configuration including an `sk-`-prefixed credential for a custom external API endpoint. The credential value is intentionally omitted from this report.

**Status:** CURRENT SOURCE FIXED — PROVIDER-SIDE ROTATION REQUIRED

**Fix applied:** replaced the file with a normal EditorConfig configuration and extended secret scanning to include `.editorconfig` files.

**Closure requirement:** revoke/regenerate the exposed credential at the external provider, place the replacement only in the deployment/user secret store, and verify the old key is disabled.

---

### SEC-014 — P1 High — Unpatched `bigint-buffer` dependency in Solana JavaScript 1.x stack

**Affected:** `solana-launcher` and `solana-subscription-service` transitive dependency trees through current Solana JavaScript packages.

The dependency audit reports the known `bigint-buffer` buffer-overflow/availability advisory. The maintained `@solana/web3.js` 1.x line still depends on the affected package and the upstream package has no patched release.

**Status:** OPEN — UPSTREAM/MIGRATION BLOCKED

**Treatment:** do not use `npm audit fix --force` to force incompatible historical Solana packages. Keep request/body/rate limits at public boundaries, track the advisory, and plan migration away from the legacy dependency chain (for example the successor Solana SDK stack) before marking this closed.

---

### SEC-015 — P1 High — Python JWT dependency chain contained unpatched `ecdsa`

**Affected:** `solana-launcher/backend` through `python-jose`.

**Status:** FIXED IN BRANCH / CI RETEST PENDING

**Fix:** replaced `python-jose` with PyJWT for the existing HMAC JWT encode/decode use, removing the vulnerable `ecdsa` transitive dependency; raised the Setuptools build requirement to the audited fixed range.

## Checks that did not reproduce a vulnerability

### Current `solana-launcher` Mini App payment ownership

`create-invoice`, `order` and `verify-payment` validate Telegram Mini App identity. Order lookup and payment confirmation bind the order to `telegram_user_id`; another user's payload is returned as not found.

### Current `solana-launcher` on-chain payment verifier

The current verifier uses finalized signatures, rejects signature and transaction errors, requires the random payment reference, exact recipient and exact amount. The P0 payment-integrity bug was confined to the older `solana-subscription-service` implementation reviewed above.

### Developer completion route

`/api/miniapp/dev-complete` is explicitly unavailable when `NODE_ENV=production`.

### Current source-level quick sink search

No indexed hits were found for direct `dangerouslySetInnerHTML`, `innerHTML`, `eval(`, `shell=True` or Python `subprocess` usage during the quick source-signature pass. This is supporting evidence only, not a substitute for full SAST.

## Residual items / blocked by runtime or provider availability

### DAST not yet executed against the live deployment

At audit time the known public deployment did not expose a reachable HTTP/HTTPS application on the probed service ports. Therefore production/staging Web-vuln-scanner, ghostmap, XHunter, browser ticwebtools and authenticated role-comparison scans are **PENDING**, not silently treated as passed.

### Credential rotation

SEC-012 and SEC-013 cannot be closed by repository edits alone. The old provider-side credentials must be revoked/regenerated and deployment secrets updated. Do not put replacement values in Git, PR comments, CI logs, tickets, or this report.

### Legacy Helius webhook defense in depth

`telegram-miniapp/backend-new` authenticates its Helius webhook and has unique payment signatures/memos, but the legacy webhook still trusts the authenticated event payload rather than independently fetching the signature from Solana RPC. If this legacy backend remains deployed, either decommission it in favor of the current `solana-launcher` payment verifier or add independent finalized on-chain verification.

### Redis defense in depth

`solana-subscription-service` keeps Redis on the private Docker network but does not configure Redis authentication. Add service credentials/ACLs or equivalent network isolation if the deployment model allows untrusted workloads on the same container network.

### Legacy API rate limiting

The legacy Mini App backend still needs an ingress/application rate-limit policy for create/status/webhook routes. Apply it at the reverse proxy or add a maintained rate-limit middleware before public exposure.

## Exit criteria

- SEC-012 and SEC-013 provider-side credentials are revoked/rotated and old credentials verified dead.
- No other open P0/P1 finding remains, or an explicit time-bounded risk acceptance exists for an upstream-blocked dependency such as SEC-014.
- Audit PR security checks pass after dependency/lockfile remediation.
- Reachable staging receives active DAST and authenticated role testing.
- Reachable production receives the conservative DAST profile.
- Any confirmed DAST finding is fixed and retested.
- Residual legacy services are either hardened to the current standard or removed from deployment.
