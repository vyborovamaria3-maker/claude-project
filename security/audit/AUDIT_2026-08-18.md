## Current status

The white-box audit, security hardening and regression-gate work are implemented on the audit branch. Live DAST is intentionally still marked **PENDING** because no authorized reachable HTTP/HTTPS deployment was available during this audit session.

Two P0 credential exposures were found. Their literal values are intentionally excluded from this report. The current source tree has been cleaned, but those findings cannot be closed until the credentials are revoked/rotated at their providers.

One upstream Solana JavaScript dependency advisory remains under a **time-bounded exception through 2026-10-01**. The CI policy allows only that exact documented advisory and fails for any other high/critical npm finding.

## Findings

### SEC-001 — P0 Critical — Failed Solana transaction could satisfy legacy payment verifier

**Affected:** `solana-subscription-service/apps/api/src/services/solana.service.ts`

**Status:** FIXED

The verifier previously checked confirmation state and intended transfer/memo content without first rejecting RPC transaction errors.

**Fix:** reject both signature-status errors and parsed transaction `meta.err` before payment-content validation. Regression tests cover both failure paths.

---

### SEC-002 — P0 Critical — Concurrent payment confirmation race

**Affected:** `solana-subscription-service/apps/api/src/services/subscription.service.ts`

**Status:** FIXED

Parallel confirmation attempts could pass the original PENDING pre-check before either update committed.

**Fix:** atomically claim exactly one PENDING payment inside the database transaction, reject subsequent claims, and extend an existing active entitlement from its future expiry instead of granting duplicate periods.

---

### SEC-003 — P1 High — Telegram Mini App replay window not enforced

**Affected:** `solana-subscription-service/apps/api/src/security/telegram.ts`

**Status:** FIXED

**Fix:** enforce a 24-hour `auth_date` maximum age, five-minute future skew, positive numeric Telegram user ID, valid user JSON and timing-safe signature verification. Regression tests cover fresh, expired and future-dated sessions.

---

### SEC-004 — P1 High — Legacy Mini App BOLA / Telegram impersonation

**Affected:** `telegram-miniapp/backend-new/src/controllers/subscriptionController.ts`

**Status:** FIXED

Payment creation trusted a client-supplied Telegram ID and subscription status accepted arbitrary user IDs.

**Fix:** both operations now derive identity only from server-verified Telegram Mini App `initData`. Status is scoped to the authenticated Telegram user and sensitive responses are `Cache-Control: no-store`.

---

### SEC-005 — P1 High — Helius webhook authentication could fail open

**Affected:** `solana-subscription-service/apps/api/src/routes/webhook.routes.ts`

**Status:** FIXED

**Fix:** an unconfigured Helius auth token disables the route with 503; configured tokens are mandatory and compared in constant time. Webhook batch and signature sizes are bounded.

---

### SEC-006 — P1 High — Production backend could start with unsafe debug/internal-auth settings

**Affected:** `solana-launcher/backend/app/core/config.py`

**Status:** FIXED

**Fix:** production startup now rejects `DEBUG=true`, wildcard CORS, default/weak admin settings and an absent/short internal `BACKEND_API_KEY`. Regression tests cover these fail-closed rules.

---

### SEC-007 — P2 Medium — Refresh cookie could remain non-Secure

**Affected:** `solana-subscription-service/apps/api/src/config/env.ts`

**Status:** FIXED

**Fix:** production authentication cookies are always `Secure`, regardless of the development override.

---

### SEC-008 — P2 Medium — JWT verification algorithm was not explicitly pinned

**Affected:** `solana-subscription-service/apps/api/src/security/tokens.ts`

**Status:** FIXED

**Fix:** JWT signing and verification explicitly use HS256 and access/refresh secrets must be distinct.

---

### SEC-009 — P1 High — Fixed SOL/USD demonstration quote could undercharge USDC checkout

**Affected:** `solana-subscription-service/apps/api/src/services/subscription.service.ts`

**Status:** MITIGATED / PRODUCTION FAIL-CLOSED

**Fix:** production USDC checkout is disabled until a live price source is configured. Development retains the deterministic demo quote only for local testing.

---

### SEC-010 — P2 Medium — Mutable GitHub Action references

**Affected:** `.github/workflows/repository-hygiene.yml`

**Status:** FIXED

**Fix:** actions are pinned to immutable commit SHAs. The repository security regression continues to enforce immutable action references.

---

### SEC-011 — P2 Medium — Legacy Mini App HTTP hardening gaps

**Affected:** `telegram-miniapp/backend-new/src/index.ts`, `src/config/index.ts`

**Status:** FIXED

**Fixes:** disabled `X-Powered-By`, bounded JSON to 256 KiB, added baseline security headers, validated ports/URLs/secrets, require HTTPS frontend in production, and added explicit proxy-trust validation.

---

### SEC-012 — P0 Critical — Telegram bot credential committed in source/history

**Affected current paths before remediation:** `telegram-miniapp/bot/bot.ts`, `bot.js`, `set-menu-button.js`.

**Status:** CURRENT SOURCE FIXED — PROVIDER-SIDE ROTATION REQUIRED

**Fix applied:** removed every hardcoded fallback credential, require runtime environment values, added a safe `.env.example`, stopped logging full Mini App payloads, and added redacted current/diff secret gates.

**Closure requirement:** revoke/regenerate the exposed Telegram bot credential, update deployment secrets, redeploy and verify the old credential is invalid. Git-history rewriting is optional defense in depth after rotation; it is not a substitute for rotation.

---

### SEC-013 — P0 Critical — External API credential embedded in `.editorconfig`

**Affected current path before remediation:** `solana-launcher/.editorconfig`.

**Status:** CURRENT SOURCE FIXED — PROVIDER-SIDE ROTATION REQUIRED

The file contained unrelated provider configuration with an `sk-`-prefixed credential for a custom external API endpoint.

**Fix applied:** replaced the file with a normal EditorConfig file and included `.editorconfig` in secret scanning.

**Closure requirement:** revoke/regenerate the exposed credential at the issuing provider, store the replacement only in the intended secret store and verify the old key is disabled.

---

### SEC-014 — P1 High — Unpatched `bigint-buffer` dependency in Solana JavaScript 1.x chain

**Affected:** Solana JavaScript dependency trees used by `solana-launcher` / `solana-subscription-service`.

**Status:** OPEN — UPSTREAM/MIGRATION BLOCKED — EXCEPTION EXPIRES 2026-10-01

The upstream package has no patched release in the current legacy Solana dependency chain. Forcing npm's incompatible historical remediation is not considered a valid fix.

**Treatment:**

- keep public request/body/rate limits;
- run on Node 22;
- allow only the exact documented `bigint-buffer` high advisory in CI;
- fail CI on any other high/critical npm advisory;
- automatically fail the exception after 2026-10-01;
- plan migration away from the legacy dependency chain before expiry.

---

### SEC-015 — P1 High — Python JWT dependency chain included unpatched `ecdsa`

**Affected:** `solana-launcher/backend` through `python-jose`.

**Status:** FIXED IN BRANCH — CI RETEST PENDING

**Fix:** replaced `python-jose` with PyJWT for the existing HMAC JWT encode/decode flow, removing the vulnerable `ecdsa` transitive dependency. The Setuptools build requirement is also raised to the audited fixed range.

---

### SEC-016 — P1 High — Legacy Helius event trusted as payment truth / non-atomic entitlement

**Affected:** `telegram-miniapp/backend-new` webhook/payment flow.

**Status:** FIXED IN BRANCH — CI BUILD RETEST PENDING

**Fixes:**

- Helius remains an authenticated notification source only;
- before entitlement, the backend independently fetches the transaction from Solana RPC with `finalized` commitment;
- rejects failed transactions;
- requires the opaque random payment memo in finalized RPC data;
- verifies the merchant's USDT token-balance delta equals the expected amount;
- payment claim and subscription extension are performed atomically so duplicate webhook deliveries cannot grant duplicate time.

---

### SEC-017 — P2 Medium — Legacy API had no application-level rate limit and env template mismatched Prisma

**Affected:** `telegram-miniapp/backend-new`.

**Status:** FIXED

**Fixes:**

- bounded fixed-window rate limits for subscription and webhook endpoints;
- bounded limiter state to prevent unbounded memory growth;
- explicit `TRUST_PROXY_HOPS` setting for correct client-IP handling behind a trusted reverse proxy;
- `.env.example` now matches the service's actual Prisma SQLite datasource instead of showing an incompatible PostgreSQL URL.

For multi-replica deployments, an ingress/shared-store rate limit remains recommended as defense in depth.

## Checks that did not reproduce a vulnerability

### Current `solana-launcher` Mini App payment ownership

`create-invoice`, `order` and `verify-payment` validate Telegram Mini App identity. Order lookup/payment confirmation bind the order to `telegram_user_id`; another user's payload is treated as not found.

### Current `solana-launcher` on-chain verifier

The current verifier uses finalized signatures, rejects signature and transaction errors, requires the random payment reference, exact recipient and exact amount. The original P0 payment-integrity bug was confined to the older subscription-service implementation.

### Developer completion route

`/api/miniapp/dev-complete` is unavailable when `NODE_ENV=production`.

### Quick source sink pass

No indexed hits were found for direct `dangerouslySetInnerHTML`, direct `innerHTML`, `eval(`, `shell=True` or Python `subprocess` in the quick source-signature pass. This is supporting evidence, not a substitute for full SAST.
