## Operator migration and existing-data caveats

1. **Previously issued bad TG Mint proofs are not retroactively revalidated by this PR.** Treat existing `tg_token_candidates` `confirmed_token`, `tg_token_mentions` and Intelligence `token_link_observations` generated by the *old base64 detector* as potentially untrusted until audited against initialized parsed SPL Mint at an appropriate finalized/confirmed slot. Existing false positives need append-only `token_links_invalidated` evidence (or a separately reviewed quarantine view), not silent deletion of historical rows.
2. Old `not_token` statuses from the previous permanent-negative check are **not automatically mass-updated**. Re-evaluate through a scoped, backed-up, reviewed maintenance procedure on the user's real local database. The new `ambiguous` state is retryable and bounded (24 hours per candidate).
3. **Migration 004 is mandatory** for any new local ETL process. Apply migrations in order 001, 002, 004 (003 if feature store in use) to the **separate Intelligence target** and rehearse DB restore on an isolated copy. Never apply migrations to X/TG source DB through Intelligence API.
4. Switching `X_INTELLIGENCE_OUTBOX_ENABLED` or `TG_INTELLIGENCE_OUTBOX_ENABLED` **off** stops all new source events, including tombstones. If source collection continues while off, do **not** interpret previously confirmed token links as current. Keep authoritative source revisions and schedule an explicit reconciled replay before exposing active links.
5. The existing source Outbox may hold **dead-letter events** from earlier failed deliveries. There is no automatic mass reset/replay. Inspect counts with ARCH-09, review error reason and backup, and replay only after verifying the migration and schema.
6. The mint RPC verification uses **confirmed** account state at the check time; it is not a historical attestation of account state at the message's original posting time. `occurredAt` and `observedAt` remain separate, and prior evidence should never be promoted to a no-lookahead signal.
7. The existing single-machine localhost-only API and Next.js proxy remain **off** unless explicitly enabled. No source collectors, credential connections, browser sessions, Docker networking, migrations or background workers are started by this PR.

## Not claimed as solved

- Full historical X/TG or Blockchain coverage; data loss before collecting old edits/deletes is fundamentally unrecoverable from current snapshots.
- Solana trade ownership, attribution and PnL; wallet evidence does not imply token trade.
- Legacy false-positive mint claim re-verification on real data; requires a separate safe migration/quarantine.
- Renewal protection for `etl:once --limit > 1` events waiting their turn, SQL pagination/index optimization, same-millisecond retraction ordering, and distributed ingress IP trust. These are P2 backlog.
- Live production rollout, backup/restore or long-running load tests.
