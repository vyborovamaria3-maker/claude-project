# Telegram signed peer parity — исправление канонической идентичности

Проверено 2026-10-20. Общие контракты `packages/contracts/src/canonical-ids.ts` уже допускают канонический `tg:source:-100123...`, а native Telegram Outbox исторически требовал только положительный `peer_id`. Это приводило к отказу публикации в Intelligence для числовых идентификаторов каналов со знаком минус. Отрицательный ID — **не** username и не внутренний surrogate ID.

## Исправление

- `tg-collector/src/persistence/outbox.ts`: разрешены положительные и отрицательные целые peer ID, без пробелов, `+` и ведущих нулей, сохраняя знак точно. Правило применяется ко всем новым Telegram сообщениям, soft-delete, on-chain-verified mint links и source-level retractions.
- `intelligence/scripts/backfill-core.mjs`: legacy TG снимки с подписанным peer теперь создают `tg:source:-100...` и `tg:message:-100...:<messageId>`, без подстановки локального source_id.
- `intelligence/scripts/quality-core.mjs`: историческая выборка учитывает подписанные числовые ID как потенциально пригодные, а не ложно классифицирует их как отсутствие стабильного peer.
- Unit-тесты проверяют четыре типа Telegram событий, backfill и отчёт, в том числе отклонение `@channel`, `+123`, `-0`, `0` и строк с пробелами.

## Rollout / backfill

Правка не меняет существующие ID, таблицы и schema migrations. Не запускает Telegram API или XActions, не включает флаги и не трогает существующую рабочую базу.

**Ранее завершённый исторический backfill мог пропустить отрицательные peer IDs.** История не может считаться полной только по старому checkpoint. После проверки актуальной базы и её резервной копии нужен новый ограниченный проход ARCH-08 с новым уникальным `--scope` и `--checkpoint`, проверка `excluded` и source-outbox→Intelligence доставки. Повторные одинаковые события по текущим immutable IDs допускают idempotent replay, но у ранних записей могут быть другие наблюдения и версии — провести аудит, не перезаписывая их.

Особая граница: поддержка signed ID подтверждает *стабильность текстового идентификатора*, не даёт права считать Telegram тикер или найденный адрес проверенным токеном.

Работа зависит от ветки ARCH-09 и предыдущих PR #139/#137/#136/#135/#134/#133; PR нельзя мёрджить без CI и ревью.
