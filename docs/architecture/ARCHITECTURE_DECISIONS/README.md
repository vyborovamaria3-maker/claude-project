# Architecture decision records (ADRs)

ADRs make **proposed vs accepted** system choices explicit. An ADR is not evidence that deployment or a customer pilot occurred. Review and mark an ADR **Accepted** only after the relevant owner approves it and the implementation is assessed.

| Record | Status | Decision |
| --- | --- | --- |
| [ADR-0001](0001-independent-evidence-and-runtime-boundaries.md) | Proposed | Independent source databases and evidence-first cross-source identity |
| [ADR-0002](0002-token-intelligence-mvp-focus.md) | Proposed | One verified-mint Token Intelligence MVP, other services remain modules or separate products |

For audit and implementation gates, see [DATA_CONTRACTS](../DATA_CONTRACTS.md), [KNOWN_GAPS](../KNOWN_GAPS.md), [LIVE_TESTS](../LIVE_TESTS.md), [PR_STATUS](../PR_STATUS.md), and [DELIVERY_PLAN](../DELIVERY_PLAN_20261024.md).
