# ARCH-05b — проверка Solana mint в X Collector через Alchemy

Статус: **draft PR #137**, изменения поверх #136 → #135 → #134 → #133. Данные в рабочих X/Telegram/Blockchain PostgreSQL/SQLite не изменены. Это не доказательство live-готовности.

## Принцип

Найденный в твите base58-адрес **не считается** автоматически токеном. Реестр `archive_tokens` и таблица `tweet_token_links` подтверждают текстовое совпадение, но не существование SPL Mint аккаунта on-chain.

Новый X-процесс обращается к **Alchemy Solana RPC** с `getAccountInfo` и `jsonParsed`, проверяет:
- владелец аккаунта — официальный SPL Token или SPL Token-2022 program;
- RPC возвращает `parsed.type = mint`, а не `account`/wallet/ATA;
- аккаунт инициализирован, количество decimals допустимо;
- проверка выполняется для точного адреса, присутствующего в сохранённом тексте твита.

Это проверка существования Mint-аккаунта в момент RPC-запроса, **не** проверка ликвидности, безопасности, цены, владения кошельком, качества мемкоина или будущей доходности.

## Безопасный локальный запуск

Из папки `x-collector` на ноутбуке (Windows PowerShell):

```powershell
# По умолчанию ТОЛЬКО прочитать из БД сохранённые твиты:
npm run intelligence:verify-x-mints -- --limit=20 --cursor=0
```

Для ручного полноценного прогона **после backup/restore и проверки миграций** оператор должен отдельно настроить конфиденциальные переменные `DATABASE_URL` и `ALCHEMY_SOLANA_RPC_URL` (не записывать реальные значения в репозиторий), а также явно разрешить:

```powershell
$env:X_INTELLIGENCE_OUTBOX_ENABLED='true'
$env:X_INTELLIGENCE_TOKEN_LINKS_ENABLED='true'
$env:X_INTELLIGENCE_MINT_VERIFY_ENABLED='true'
npm run intelligence:verify-x-mints -- --execute --limit=20 --max-rpc=20 --cursor=0
```

Не запускать пример на реальной базе без предварительной проверки резервной копии, существования миграции X 050 и Intelligence 004, готовности локального ETL-потребителя и обособления PostgreSQL-соединений. Флаги **по умолчанию выключены**.

Ограничения: `--limit` и `--max-rpc` 1–50, максимум три адреса на твит; повторные адреса в одном запуске используют кеш RPC. JSON-ответ процесса содержит только счётчики и `nextCursor`, пригодный для ручного следующего батча. При сбое проверки запись не подтверждается, код ошибки RPC/URL не печатается; `deferred` требует отдельного повторного прохода с прежним курсором (иначе история будет неполной).

**Важно:** `--execute` — платные/лимитируемые внешние RPC-запросы. По умолчанию это не фоновый сервис, не браузерный XActions и не запуск коллектора, а отдельная ограниченная операция.

## Транзакции и ревизии

Второй этап обработки, после сетевого RPC, выполняется внутри X PostgreSQL-транзакции. Твит повторно читается под `FOR UPDATE`. Если его текст, автор или дата публикации изменились, запись проверки пропускается, старый адрес нельзя автоматически подтверждать по устаревшему снимку.

При обычном сохранении X Collector, **только с включёнными флагами**, изменение текста твита публикует `token_links_invalidated` в той же транзакции, что и новые данные. Изменение только метрик не отзывает токеновые связи.

Событие `token_link_verified` содержит ссылку на доказательство, хеш версии текста, Solana mint ID и метод проверки SPL аккаунта. Сам текст, MTProto/X сессии, cookie и RPC-ключи не экспортируются.

Для активного состояния использовать `intelligence.queryActiveTokenLinks(...)` из ARCH-07a. Исходные записи реестра сохраняются как исторические доказательства; обычная `queryTokenTimeline` не создаёт фантомные токеновые публикации.
